# FCM Device Token Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate Firebase Cloud Messaging for drivers and delivery managers to register/deactivate device tokens, handle foreground/background/terminated notifications, and route payloads safely according to the backend contract.

**Architecture:** Core adapters (`PushMessagingGateway`, `LocalNotificationService`, `PushNotificationCoordinator`) interface with Firebase/platform plugins; a feature-based Clean Architecture slice (`DeviceTokenRemoteDataSource`, `DeviceTokenRepository`, UseCases) handles API contracts via Retrofit; domain `NotificationPayloadParser` and `NotificationRouter` handle typed payload parsing and route navigation without leaking SDK or network types.

**Tech Stack:** Flutter, Dart 3, firebase_core, firebase_messaging, flutter_local_notifications, Retrofit, flutter_bloc, flutter_test.

**Spec:** `docs/superpowers/specs/2026-09-24-fcm-device-token-integration-design.md`

## Global Constraints

- Follow `rules/rules_backend.md` and preserve the existing Clean Architecture, dependency injection, Retrofit client, repository, use-case, and view-model patterns.
- **DO NOT commit to git and DO NOT create any new git branches or worktrees.** All work must remain in the working tree as requested.
- Use the existing `lib/core/errors`/`Failure`/`ApiResult` handling. All endpoint calls return `ApiResult<void>` through `safeApiCall<void>`.
- Token synchronization is strictly best-effort and must never block authentication, driver registration, or app startup.
- Endpoint contracts:
  - Driver upsert: `POST /api/v1/driver/device-token` (pre-login passes `registrationId`, authenticated relies on driver JWT).
  - Driver deactivate: `DELETE /api/v1/driver/device-token?token={FCM_TOKEN}`.
  - Delivery-manager upsert: `PUT /api/v1/restaurants/device-tokens` with JWT.
  - Delivery-manager deactivate: `DELETE /api/v1/restaurants/device-tokens?token={FCM_TOKEN}` with JWT.
  - Platform values emitted by the app are exactly `Android` and `iOS`.
  - Android notification channel ID is exactly `mealmate_alerts_channel` with high importance.
- Never log, persist in plain text, or leak full FCM tokens, call tokens, JWTs, or complete message bodies.
- Follow TDD for every behavioral change: write a focused failing test, run and confirm RED, implement minimal production code, and confirm GREEN.
