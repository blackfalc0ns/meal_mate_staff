# Driver voice calls: implementation plan

> For Gemini: implement the checked items in this repository, then validate with the user app at `D:/projects/meal_mate__User`. Read `docs/voice-calls-driver-amendments.md` and the backend handoff supplied in the task before editing. Preserve existing changes in the working tree.

**Goal:** Make driver calling reach real two-way audio and reconcile answer, cancellation, hangup, expiry and duration with the server.

**Architecture:** Keep the existing ViewModel → repository → REST/SignalR/WebRTC layers. Treat the server snapshot as authoritative; use local media events for reports, then wait for an Active snapshot before displaying elapsed duration. Keep one call ID and negotiation generation through all stages.

**Tech stack:** Flutter, flutter_bloc, Dio/Retrofit, SignalR, flutter_webrtc, flutter_callkit_incoming.

## Findings to verify during implementation

- `driver_active_call_screen.dart` always sends `EndCallEvent`, even in Created/Ringing, then immediately pops. `driver_calling_view_model.dart` ignores the API result and emits Ended. The backend says Ringing requires caller `/cancel`; `/end` only permits Accepted/Connecting/Active.
- `driver_voice_call_signalr_client.dart` invokes `BindDeviceSession` with only the session ID. Compare the deployed hub's exact argument contract; the supplied backend handoff requires `[deviceSessionId, controlProof]`. Its answer/ICE listeners and payload parsing need contract verification against the user app and backend.
- `driver_webrtc_manager.dart` marks local media Active on peer/ICE connected. No driver `/reports/connecting` or `/reports/connected` path was found in the calling repository; backend Active requires reports from both peers. The ViewModel timer starts on local Active instead of authoritative `connectedAtUtc`.
- A failed ICE lookup currently permits offer creation with an empty server list. TURN readiness is an external deployment check, not an app constant to replace.

- [ ] **5. Never swallow a missing ViewModel and pop as though a request succeeded. Check ApiResult and show recoverable failure; on 409 fetch the snapshot and reconcile. - [ ] **6. Reconcile remote termination and reconnection.** On terminal `call:event` or push, verify call ID/sequence, stop tracks, close CallKit and screen once. After reconnection, foreground resume or a suspected missed event, fetch active/current snapshot; terminal or absent calls must close stale UI. Keep Arabic/English strings in localization resources.
- [ ] **7. Verify integration.** Run focused Flutter tests, `flutter analyze` on touched code, and two-device calls on different networks: unanswered cancel, either-party end after answer, expiry at deployed deadline, foreground/background, network switch and reconnect. Capture matching call ID and terminal sequence on both clients, successful server Active only after both reports, bidirectional RTP counts and audible media. Check deployed TURN DNS, authenticated allocation and relay independently; escalate infrastructure failure with evidence instead of hardcoding another host.

**Acceptance:** The driver cannot show a successful hangup solely because its screen closed. Both clients end the same call, ringing expires at the server deadline, duration starts at server Active, and real-device audio is audible both ways. Local unit tests alone cannot certify TURN or media.
